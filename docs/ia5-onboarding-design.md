# IA5 首启引导设计（三步添加课表）

> 对应《界面优化方向清单》**IA5 首启引导与空态闭环**。
> 本文只做**设计**，不含实现；确认后再动代码。
> 状态：**待确认**（方案 A / B / C 三选一）

## 1. 清单要求与现状

清单原文：

> 首启提供「三步添加课表」引导；所有空态一律给出可执行的下一步入口。
> 目标：降低首启流失；把「没数据」变成「知道怎么加数据」。

**现状**（已核实）：

| 项 | 状态 |
|---|---|
| 首启引导流程 | **不存在**（全库检索 `onboarding` / `firstLaunch` / `isFirstRun` / `welcome` 零命中） |
| 空态可执行下一步 | **已部分完成**（v3.69.4：`AppEmptyState` 支持 `actionLabel`+`onAction`，课表空态已接「课表导入/导出」） |
| 添加课表的入口 | **共 4 条**，见下节 |

## 2. 「添加课表」的四条路径（引导要指向哪条？）

| 路径 | 入口 Destination | 适合谁 |
|---|---|---|
| **① 教务系统导入** | `SchoolSelectionListScreen` → 登录 → 导入 | **绝大多数学生**（首选） |
| ② 文件导入 | `FileImportHub` → `ExcelImport` / `JsonFileImport` | 已有导出文件 / 从旧设备迁移 |
| ③ 文本导入 | `TextImportHub` | 手工整理的课表 |
| ④ 手动添加课程 | `AddEditCourse` | 课少、不想登录教务 |

⇒ 「三步添加课表」**应指 ①**（覆盖面最广），并在引导里给「其他方式」的次入口，
把 ②③④ 收在二级，避免首启就把四条路平铺给用户（那正是"不知道点哪个"的来源）。

## 3. 三个方案对比

### 方案 A · 首启全屏引导（Onboarding 页）

独立 3 屏横滑：`欢迎 → 选择学校 → 完成`，走完进主界面。

- ✅ 仪式感强、路径最清晰
- ❌ 需新增整页流程 + 首启状态存储；**对已装用户是干扰**（升级后也可能撞见）
- ❌ 用户若这次不想导入，还得先划完 3 屏才能用 App —— 与"降低流失"的目标相反

### 方案 B · 增强空态（在课表页空态里显示三步）

把已完成的空态动作按钮升级为「三步说明卡 + 主按钮」。

- ✅ **零新页面**、无首启状态存储、与已完成的空态闭环天然衔接
- ✅ **可反复触达**（只要还没课表就一直在），不像全屏引导那样"错过就不再"
- ✅ 对已装用户零干扰（只在真的没数据时出现）
- ❌ 引导性弱于全屏；用户若从「我的」等页面进入，看不到它

### 方案 C · 首启弹层 + 空态常驻卡（B 的增强）

在 B 的基础上，增加"首次进入时用底部弹层说明一次三步"，关闭后由空态卡接管。

- ✅ 兼顾"首启被明确告知"与"之后仍可找回"
- ❌ 需要**首启状态存储**（新增 DataStore 字段）；弹层多一次打断

## 4. 推荐方案：B（推荐）/ C（可选增强）

### 为什么推荐 B

1. **触发条件更本质**：真正决定"要不要引导"的不是"第几次启动"，而是**"有没有课表"**。
   按数据判断 ⇒ 无需新增首启 flag、无状态迁移、对老用户天然友好。
2. **与已完成工作衔接**：v3.69.4 刚给 `AppEmptyState` 加了 `actionLabel`/`onAction`，
   课表空态已接上「课表导入/导出」。B 只是把这一处从"一个按钮"扩展为"三步说明 + 按钮 + 其他方式"。
3. **可反复触达**：全屏引导的典型失败是"用户当时跳过了，之后再也找不到"；
   空态则一直在。

### B 的具体设计

课表页空态（`WeeklyScheduleScreen` 的 `pageCourses.isEmpty()` 分支）由
「一句话 + 一个按钮」改为：

```
┌─────────────────────────────────────┐
│           这周还没有课程              │
│                                       │
│   ① 选择学校   ② 登录教务   ③ 完成导入  │   ← 步骤条（横向三段）
│                                       │
│      [ 从教务系统导入 ]                 │   ← 主按钮（实心主色）
│       其他添加方式 ›                    │   ← 次入口（文字按钮 → 展开/二级）
└─────────────────────────────────────┘
```

- **主按钮** → `Destination.SchoolSelectionListScreen`（教务导入，覆盖面最广）
- **「其他添加方式」** → 展开显示 `文件导入 / 文本导入 / 手动添加课程` 三个文字入口
  （不在首屏平铺，避免"不知道点哪个"）
- **步骤条**仅为示意，不可点击（纯视觉引导，不做交互步骤机）—— 避免引入状态机复杂度

### C 的增强部分（**可选**，需你决定）

若希望"首启被明确告知一次"，再加：

- 首次启动且无课表时，进入课表页弹一次底部弹层，内容同步骤条 + 主按钮；
- 关闭后不再自动弹（持久化一个 `hasSeenAddScheduleGuide` 布尔）；
- 空态卡始终保留（不依赖该 flag）。

**代价**：新增 DataStore 字段（含迁移）+ 首次启动的打断。
**收益**：用户不会"进了 App 但不知道要点哪"。

## 5. 实现要点与风险

| 项 | 说明 |
|---|---|
| 改动面 | 主要改 `WeeklyScheduleScreen` 空态分支；若用 C 再加 DataStore 字段与弹层 |
| 复用 | 复用 `AppEmptyState`（已有 `actionLabel`/`onAction`）；步骤条需新增小组件 |
| ⚠️ **字符串资源** | 三步文案（"选择学校""登录教务""完成导入"）需新增。**此前新增 `composeResources` 字符串后编译器持续报 `Unresolved reference`，根因未明**（clean / `--rerun-tasks` / 清缓存均无效）。⇒ 实现前需先做**最小验证**：只加一个字符串跑通编译，再批量加。若仍失败，退路是复用现有文案（如 `item_school_system_import`、`section_school_import`）拼出引导 |
| 不做的事 | 不做可点击的分步状态机（步骤条仅示意）；不阻塞用户——任何一步都可跳过，用户随时能去别的页面 |

## 6. 验收方式

- **走查**：清空课表数据 → 课表页应显示三步引导；点主按钮应进入学校选择页；
  点「其他添加方式」应能看到三个次级入口
- **装机**：`adb shell pm clear com.shangkeschedule`（**会清数据，需确认**）后冷启动走一遍；
  或不卸载、直接在设置里删掉所有课表
- **不回归**：有课表时**不得**出现引导；无课表的其它页面不受影响
