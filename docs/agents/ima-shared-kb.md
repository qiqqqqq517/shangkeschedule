# IMA 项目记忆协作细则

> 入口与优先级见仓库根 `AGENTS.md`。本文件维护 IMA 专项流程，历史记录不自动成为现行规则。

## 1. 按需读取

- 接手现状、追溯决策、修改已有模块约定或发布口径时，先查 IMA 再用仓库核实事实。已知主题直接 `find`；不知道从何查起才读《01-总览 / 项目索引》。
- 一次先读最相关的 1–2 篇，信息不足再扩展。默认不跑全库 `ls`、不通读全部进度/复盘；索引中的版本、数量、路径只是取材时的快照。
- 同一会话保留已解析的条目与结论，未变化不重复查询。纯文案/链接修正、只读查代码无需强制联网查 IMA。
- 入口不可用时记录 `msg`，用仓库与工作日志继续可独立完成的工作；不编造已读/已回写状态。若缺失决策影响正确性，暂停该依赖步骤。

## 2. 知识库与落点

**「上课-共享」是项目记忆唯一写入目标**；个人库「上课」仅作 `--backup` 镜像。冲突以共享库为准，代码事实以当前仓库和实际验证为准。

| 文件夹 | 内容 |
| --- | --- |
| `01-总览` | 项目索引、规则、协作指南 |
| `02-架构与模块` | 架构、模块、数据库 |
| `03-运行部署` | 构建、发版、部署 |
| `04-接口文档` | 接口契约、协议 |
| `05-决策记录` | 选型、取舍、踩坑与被推翻的方案 |
| `06-进度与待办` | 本轮结果、阻塞、下一步 |
| `07-问题复盘` | 巡检、事故、检查报告 |
| `08-资料归档` | 外部资料、历史快照 |

目录编号固定；知识库与文件夹 ID 按名称现场解析，不写进文档或脚本常量。条目数量需盘点时现场查询，不维护静态总数。

## 3. 写入触发与去重

- 架构/接口/规则/决策/问题状态变化时，更新对应篇章。每轮有改动的收尾写一次简洁进度；仅问答、无变化的重复巡检不制造新条目。
- 先 `find` 查重：长期主题优先追加现有笔记；不存在时 `note-new`。一次性报告才 `up`，不把同一份全文再复制到多个文件夹。
- 本轮变化若已完整记录在一篇主题笔记，进度/索引仅追加一句结果与该条目标题；只有导航或规则入口变化才更新索引，不为普通修复重复追加索引。
- 新内容头部必须有 `取材版本 / 生成时间 / 作者`。只追加或留痕更正；结论变化明确写「原结论 → 新结论 → 依据」，点名被推翻的旧记录。
- 标题短且可独立表意，主题/日期置前；避免中段 `v2/rev2`（历史上被吞字），版本可置末尾。入库后回查实际标题，防截断和撞名。
- 本地 Markdown 草稿保存在 `build_qa/ima-init/notes/`。不写密钥、签名凭据、他人隐私、内部 ID。

## 4. 统一命令与安全门

写入一律经 `scripts/ima_kb.cjs`。依赖 `ima-skill`（默认 `~/.dsh/skills/ima-skills/`，可用 `IMA_SKILL_DIR` 指定）；凭证在 `~/.config/ima/`，不输出值。

```powershell
node scripts/ima_kb.cjs find '<主题>' --json
node scripts/ima_kb.cjs ls --folder 01-总览 --json   # 仅查指定层级，不递归盘点
node scripts/ima_kb.cjs read <note_id或media_id> --head 2000
node scripts/ima_kb.cjs read <note_id或media_id> --tail 2000   # 如只需最新追加

# 新建前先检索查重；预演成功后再实写
node scripts/ima_kb.cjs note-new '<标题>' '<草稿.md>' --folder 01-总览 --dry-run
node scripts/ima_kb.cjs note-new '<标题>' '<草稿.md>' --folder 01-总览 --backup
# 追加现有笔记，marker 用实际回读后的纯文本
node scripts/ima_kb.cjs note-append <note_id或media_id> '<补充.md>' --marker '<本次唯一纯文本标记>' --dry-run
node scripts/ima_kb.cjs note-append <note_id或media_id> '<补充.md>' --marker '<本次唯一纯文本标记>'

# 一次性文件，保持原始内容；先预演再上传
node scripts/ima_kb.cjs up '<报告.md>' --folder 07-问题复盘 --dry-run
node scripts/ima_kb.cjs up '<报告.md>' --folder 07-问题复盘 --backup
node scripts/ima_kb.cjs verify '<标题片段>' --folder 07-问题复盘
```

- `find/ls --json` 返回标题和媒体引用，直接传给 `read/note-append`，CLI 内部解析笔记 ID；无需另写脚本获取 ID。引用只供工具内部使用，最终答复仍用库名/标题。`find` 有后续页时按返回 `nextCursor` 用 `--cursor` 继续，不默认拉全量。
- `--head/--tail` 仅限制显示字符并明确标记截取范围；需要完整原文时去掉限制，不能把片段当全文已审阅。保持已有数字 note_id 调用兼容。
- 笔记写入前验证标题/正文为合法 UTF-8；PowerShell 读文件带 `-Encoding utf8`。若直接发请求，PS 5.1 的 JSON Body 必须用 UTF-8 字节数组。
- 文件上传顺序固定：`preflight → check_repeated_names → create_media → COS → add_knowledge`；任一步失败停止后续步骤并报告 `msg`。`folder_id` 必须在 `add_knowledge` 顶层。
- `note-append --marker` 禁用源 Markdown 标记：回读会去掉标题、粗体、反引号等，须选回读中确实存在的唯一纯文本，防重复追加。
- 入库后核对文件夹列表中的条目与父目录，并 `find` 回查标题；检索可能滞后，以正确文件夹列表落点为准，不因搜索未命中重复上传。现有 `verify` 已实现此判据。
- 备份失败只报告备份失败，不重做已成功的共享库写入。IMA 无可用的删除/改标题 OpenAPI，错误条目需人工处理，不能自动覆盖。

## 5. 历史记录处理

旧笔记中的个人库主写入、全库固定条目数、每次更新都重写索引数字等口径已被本次规则替代。后续维护只补与任务有关的差异，不逐篇重写历史快照。遗留重复条目、测试库仅按用户明确指令人工清理。
