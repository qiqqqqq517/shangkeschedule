# 三主题对比度审计（AC1）

> 对应《界面优化方向清单》**AC1 对比度审计全覆盖**。
> 建立原因：此前对比度校验只覆盖**桌面小组件**那套独立色表
> （`scripts/check_widget_contrast.py`），App 内正文只跑过一次**书卷**配色；
> 另外两套（含**默认的通透**）从未审过，而设计规范文档也只覆盖书卷。

## 结论速览

| 场景 | 不达标项 | 主要问题 |
|---|---|---|
| 通透 · 浅色 | **12** | 次要文本偏淡、语义图标在软底上过浅、徽标白字 |
| 通透 · 深色 | 4 | 主色底白字、徽标、底栏选中态 |
| 柔绘 · 浅色 | **13** | 语义图标在软底上几乎不可辨（amber 仅 1.62）、次要文本、徽标 |
| 柔绘 · 深色 | 2 | 底栏选中态、次要文本临界 |
| 书卷 · 浅色 | 6 | 主色底白字、info/amber 软底、徽标 |
| 书卷 · 深色 | **0** | — |
| **合计** | **39 / 132** | — |

两条最值得注意的结论：

1. **深色主题普遍优于浅色**，书卷深色**零不达标**；问题集中在浅色主题。
2. **唯一有设计规范的书卷配色问题最少；而作为默认主题、此前完全没有规范的通透，
   浅色下有 12 项不达标。** 这与「规范只覆盖 1/3 主题」的历史缺口直接相关。

## 方法（为什么用运行时探针）

`desktopApp/src/main/kotlin/com/shangkeschedule/ContrastProbe.kt`

```bash
./gradlew :desktopApp:run "-PpreviewMainClass=com.shangkeschedule.ContrastProbeKt"
```

- 直接调用 `appColorTokens(isDark, preset)` 取**真实渲染值**，而不是解析源码 ——
  三套 Style 的颜色是混合写法（字面量 / 常量引用 / 带 alpha 的软色），静态解析要复刻
  常量表与 alpha 合成，容易与真实值产生偏差。
- **半透明必须逐级合成**：`inputBg`（12% 填充）、`navSelectedBg`（主色 12% 胶囊）、
  `navBarBg`（玻璃底）都不是不透明色，必须先合成到其实际叠放的父表面再算对比度。
  初版漏了这一步，算出 `textSecondary on inputBg = 1.34`、`navSelectedBg` 上 2.63 这类
  显然不成立的值。
- 报告产出在 `build_qa/contrast_probe/report.md`（含全部 132 项明细与色调值）。

## 判据

WCAG 2.2 AA：正文文本 ≥ **4.5:1**；大号文本 / 非文本 UI ≥ **3:1**。本项目中按实际用途做了三处校准
（每一处都有代码依据，避免误报，详见下表备注）：

| 配对 | 判据 | 依据 |
|---|---|---|
| 语义色 on 语义软底 | 3:1（非文本） | 软底全库唯一消费点是 `iconBg = colors.successSoft`，承载的是**图标**而非正文 |
| `outline` on `cardBg` | 3:1 | M3 组件的**必要**边界（OutlinedButton / OutlinedTextField 描边） |
| `divider` on `cardBg` | 仅记录 | 本项目只作列表**装饰性**分隔，不代表可交互边界 |

## 分类发现

### 1. 次要文本 `textSecondary` 偏淡（13 项）

| 场景 | on pageBg | on cardBg | on inputBg |
|---|---|---|---|
| 通透·浅色 | 2.92 | 3.26 | 2.84 |
| 柔绘·浅色 | 3.16 | 3.38 | 3.01 |
| 书卷·浅色 | 4.92 ✅ | 4.71 ✅ | 4.27 |
| 通透/柔绘/书卷·深色 | 7.3 / 5.9 / 7.4 ✅ | — | 4.45 / 4.33 / 5.23 |

- 影响：副标题、说明文字、未选中态标签在浅色主题下偏淡，强光环境下可读性差。
- 注意：通透的 `textSecondary #8E8E93` 正是 **iOS `systemGray`**，是跟随 iOS 规范的取值；
  这是「对齐 iOS 观感」与「满足 WCAG」之间的取舍，**不宜单方面改动**。

### 2. 语义色图标 on 语义软底过浅（13 项）

| 场景 | 最差项 | 数值 |
|---|---|---|
| 通透·浅色 | `amber` on `amberSoft` | **1.43** |
| 通透·浅色 | `info` / `warning` / `success` | 1.75 / 1.99 / 2.01 |
| 柔绘·浅色 | `amber` / `warning` / `success` / `info` … | 1.62 / 1.89 / 2.24 / 2.23（全部 7 项均不达标） |
| 书卷·浅色 | `info` / `amber` | 2.47 / 2.87 |
| 三主题·深色 | — | 全部达标 ✅ |

- 影响：浅色主题下「淡色圆底 + 同色系图标」的组合，图标与底几乎融在一起
  （`amber` 1.43 意味着淡黄底上的黄图标基本看不清）。
- 深色主题没有这个问题（软底在深色下更暗、图标更亮），说明这是**浅色配方**的问题。

### 3. 主色底上的文字 `textOnPrimary on primary`（4 项）

| 场景 | 数值 |
|---|---|
| 通透·浅色 / 深色 | 4.02 / 3.65 |
| 柔绘·浅色 | 3.44 |
| 书卷·浅色 | 3.90 |
| 柔绘·深色 / 书卷·深色 | 6.28 ✅ / 5.90 ✅ |

- 影响：主色按钮、主色胶囊上的白字。属**品牌色固有**问题（Apple / Google 自家产品同样如此），
  通常靠「按钮文字按大号文本处理」或改用深色文字来缓解。

### 4. 徽标文字 `badgeFg on badgeBg`（4 项）

| 场景 | 数值 |
|---|---|
| 通透·浅色 / 深色 | 3.55 / 3.41 |
| 柔绘·浅色 | **2.77** |
| 书卷·浅色 | 3.90 |
| 柔绘·深色 / 书卷·深色 | 7.38 ✅ / 5.90 ✅ |

- 影响：未读数徽标、状态徽标的文字偏难读，柔绘浅色最差。

### 5. 底栏选中态 `primary on navSelectedBg`（5 项）

| 场景 | 数值 |
|---|---|
| 通透·浅色 / 深色 | 3.26 / 3.58 |
| 柔绘·浅色 / 深色 | **2.83** / 3.86 |
| 书卷·浅色 | 3.12 |

- 成因：选中项用「**主色文字 + 主色 12% 淡底**」，同色系天然低对比。
- 这是**有意的设计取舍**——`NavigationComponents.kt` 的注释显示，项目曾试过「选中固定主色」
  与「对比增强」两种方案，最终选择**用选中项字号加粗（11sp→12sp）来补偿**而非提高对比度。
  故此项**不建议按 WCAG 单方面改动**，但应知悉其对比度水平。

## 非缺陷项（已在报告中标注，不计不达标）

- **柔绘的 `outline` 极淡**（浅色 1.39 / 深色 1.98）：该主题显式采用低对比描边，
  「无锐利硬边缘」是既定设计语言，且这是为消除全站唯一残留的 1dp 硬灰描边而做的改动。
- **`divider` 普遍低对比**（1.22–1.69）：装饰性分隔线，WCAG 不强制。

## 建议（均属视觉变化，需确认后再动）

按「投入产出」排序：

1. **语义色软底配方（浅色）** —— 收益最大且**不改变色相体系**：只需把软底的 alpha
   从 12% 提到 20–24%（或把图标改用更深的同色档），即可让 13 项中的多数回升到 3:1 以上。
2. **徽标底色**（尤其柔绘 `#CC8A8A` 上白字 2.77）：可降低底色明度或改用深色文字。
3. **次要文本**（通透 / 柔绘浅色）：建议只对**强光下也需可读**的场合（如列表副标题）
   加深一档，保留 iOS `systemGray` 作为可选项 —— 需先明确是否接受「与 iOS 观感不同」。
4. **主色底白字与底栏选中态**：属品牌色与既有设计取舍，建议**维持现状**，
   仅在报告中留档，不做单方面改动。
