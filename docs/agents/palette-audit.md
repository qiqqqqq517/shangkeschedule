# 课程色板可区分性审计（V4）

> 对应《界面优化方向清单》**V4 色彩语义与可区分性**。
> 清单原文判断：「课程色板 20 色相（每 18° 一档）经 35% alpha 叠加后相邻档难分辨」。
> 本审计把这条主观判断**量化**，并定位到底卡在哪一层。

## 结论速览

同屏相邻色块的**最小色差**（CIEDE2000，正常视觉）：

| 场景 | 最小 ΔE | 易混淆色对 | 评价 |
|---|---|---|---|
| 柔绘 · 浅色 | **1.1** | #5 / #9 | 基本无法分辨 |
| 柔绘 · 深色 | **1.4** | #5 / #9 | 基本无法分辨 |
| 通透 · 浅色 | **2.5** | #2 / #9 | 基本无法分辨 |
| 通透 · 深色 | 3.4 | #2 / #9 | 相近 |
| 书卷 · 浅色 | 4.9 | #8 / #9 | 相近 |
| 书卷 · 深色 | 8.0 | #2 / #3 | 相对最好，仍 <10 |

参考判据：ΔE ≥10 明显可区分；3–10 可察觉但相近；<3 基本无法分辨。
**六个场景全部低于 10，色条主题（通透/柔绘）更是低到 1.1–3.4。**

## 两层根因（这是本次审计最重要的发现）

清单把问题归因于「alpha 叠加」，实测证实并**拆成了两层**：

**第一层 · 色板本身相邻档就偏近。**
以书卷深色（实色渲染、无 alpha 干扰）为例，色板原色的相邻档 ΔE 只有 **4.9–8.0**，
本身就在「相近」区间。色板是 12 色（不是清单写的 20 色 —— 清单该处与代码不符），
且马卡龙配色为低饱和高明度，相邻色相之间差异天然有限。

**第二层 · 色条主题的半透明淡底把所有色差再压缩一半以上。**
通透/柔绘走「深色档强调色 + 半透明淡底」（浅色 0.30 / 深色 0.38），
渲染色被拉向页面底色，两两距离随之塌缩：

| | 实色（书卷） | 淡底（柔绘） | 压缩比 |
|---|---|---|---|
| 浅色最小 ΔE | 4.9 | **1.1** | ×0.22 |
| 深色最小 ΔE | 8.0 | **1.4** | ×0.18 |

⇒ **只调色板不动渲染口径，收益有限**；而只提高填充 alpha 不动色板，
也只能把色差从 1.1 拉回 4–5（仍 <10）。两层需要一起处理。

## 色觉缺陷下的风险（比正常视觉更严重）

模拟红/绿/蓝色盲（Machado 2009，severity 1.0）后，多处色对跌到**几乎完全无法区分**：

| 场景 | 色对 | 正常 ΔE | 红盲 | 绿盲 |
|---|---|---|---|---|
| 通透·浅色 | #3 / #7 | 8.3 | **0.8** | 2.4 |
| 柔绘·浅色 | #5 / #9 | 1.1 | **0.5** | **0.6** |
| 柔绘·浅色 | #5 / #11 | 3.1 | **0.4** | **0.5** |
| 柔绘·深色 | #4 / #11 | 4.4 | 1.2 | **0.6** |
| 书卷·深色 | #2 / #4 | 15.5 | 5.0 | **0.2** |

值得注意：**书卷深色 #2/#4 在正常视觉下 ΔE 15.5（相当清楚），绿盲下却只有 0.2** ——
说明「正常视觉下达标」并不等于色盲用户可用。红绿色盲占比约 8%（男性），
这是色板设计中最容易被忽略的一类用户。

## 建议（均属视觉变化，需确认后再动）

按收益排序：

1. **先定「渲染色差」这一层：提高色条主题的填充 alpha**（0.30/0.38 → 0.45–0.55）。
   这是投入最小、对既有色板零改动的做法，可把最小 ΔE 从 1.1 拉回 4–6；
   代价是色块整体变实、更接近书卷观感（需确认是否符合「通透/柔绘要轻透」的定位）。
2. **再纠色板相邻档**：对 ΔE < 10 的相邻对（尤其绿/黄绿 #8/#9、青/青绿 #6/#7、
   紫/蓝紫 #2/#3）拉开明度差 —— 比拉色相差更有效，因为**明度差在各类色盲下都保留**。
3. **色盲友好**：不建议为色盲单独换色板（会破坏既有观感），
   但可把「明度差」作为选色与新增颜色的硬约束；AC6「色觉友好/高对比开关」可复用本探针数据。
4. **按课程 ID 稳定分配颜色**：清单提出「按索引取色 ⇒ 增删课程整屏换色」。
   当前已有 `getOrAssignColorByName`（同名同色）与 `pickLeastUsedColorIndex`（最少占用优先），
   需进一步核查是否仍存在按索引取色的路径 —— 属独立一项，本次未改。

## 方法（为什么必须测「实际渲染色」）

`desktopApp/src/main/kotlin/com/shangkeschedule/PaletteProbe.kt`

```bash
./gradlew :desktopApp:run "-PpreviewMainClass=com.shangkeschedule.PaletteProbeKt"
```

- 直接调用 **public** 的 `resolveCourseBlockColors(...)` 取回 `background`，
  再合成到课表页底色 —— 这是用户真正看到的颜色。拿色板原值算色差没有意义：
  同一套色板在「色条主题半透明淡底」与「书卷实色」下呈现完全不同。
- 色板取自 `ScheduleGridStyle.DEFAULT / IOS / SOFT`（各 12 色）。
- 色差用完整 CIEDE2000；色觉模拟用 Machado et al. (2009) 线性 RGB 矩阵（severity 1.0）。
- 全量数据：`build_qa/palette_probe/report.md`（6 场景 × 每场景最小 5 对，含色盲三列）。
