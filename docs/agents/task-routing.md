# 任务入口与流程路由

任务清楚时直接进入对应行，不先通读本表及所有专题。各任务共用“界定范围 → 最少取材 → 实施/诊断 → 对应验证 → 变化记录 → 授权收尾”。通用规则只维护在根 `AGENTS.md`。

| 任务 | 读取与执行边界 |
| --- | --- |
| 只读问答/定位文件 | 先限定路径搜索；需要决策才查 IMA，不 fetch、不构建、不改日志 |
| 先查问题/审查 | 收集证据与影响，默认报告；不把诊断自动变成修复、迭代或发布 |
| 修复/新功能/重构 | [开发流程](workflow.md)；先最小复现，再实施；[统一检查](checks.md)选范围，App 源码按验证矩阵编译/测试 |
| UI/主题/交互 | IMA 相关模块与决策；按需定位 `docs/design-system.md` 或 `docs/ux-interaction-spec.md` 相关章节，不整篇加载；运行影响范围的 UI 门禁 |
| 数据库/备份/同步 | IMA 架构/接口对应篇章，复核真实模型与迁移；相关兼容和失败路径测试 |
| 通知/小组件/日历 | IMA 平台记录及本次模块；需要时查 `docs/widget-display-optimization.md` 相关章节，实际投递/放置/系统写回按设备证据说明覆盖 |
| 学校与适配 | [适配 SOP](../adapter-sop.md)：新学校 §2–§4；能力钩子 §3.7；调试 §5；热更新 §6–§7；是否发版 §8；仅按命中章节读取 |
| 构建/正式发布 | [发版手册](release-runbook.md)；仅构建到三包校验，明确发版才执行完整对外流程；REST 故障才加载备用文档 |
| 巡检/持续修复 | [巡检流程](neverstop-watchdog.md)；默认单轮，根据范围检查；无变化不重跑、不刷消息、不重复写 IMA |
| Issue/PR/分诊 | [Issue](issue-tracker.md)与[标签](triage-labels.md)；先取元数据，正文与评论按需取；写入需用户授权 |
| 领域概念/架构决策 | [领域约定](domain.md)；仅查当前概念和相关 ADR，不为普通改动预建文档 |
| 对比度/色板/字号/性能 | 只加载 `docs/agents/` 中对应审计方法与本次判据；旧实测数是历史快照，不能当当前结果；真机测试不伪装成静态门禁 |
| 定时/监控 | 仅用户明确要求时使用宿主自动化工具，复用已有任务，通知只在有意义变化时产生；普通任务不自动注册 |

## 输出和记录预算

- 一次先读最相关的 1–2 篇或对应行段；已有稳定结论优先复用，不重复检索、计划、编译、总结。信息不足才扩大范围。
- `rg --files` 先定位，再 `rg -n`/限行读取；完整大文档、全库列表、全量评论、全量 diff 仅在任务确实需要时展开。
- 工具默认拿机器摘要；完整日志落 `build_qa/`，失败只提取相关上下文。不要反复把同一全文同时发给多个工具/聊天。
- 简单任务直接实施；计划随任务变化维护一份，不额外制造设计稿、计划稿、复盘稿和多份相同结论。
- 本地工作日志记录一次结果，IMA 对主题保留一份正文，进度只写结果/下一步与主题引用。未发生项目变化的查询或重复全绿不写入。
- 用户途中补充要求时继续当前任务，把新范围并入同一轮收尾，不把每条补充都变成一次 bump/提交/发版。
- 专项文档和 Skill 里的历史固定数字、额外确认或全量步骤若与当前用户授权/根规则冲突，依据现行规则解释并执行；不因此停下重复询问。
